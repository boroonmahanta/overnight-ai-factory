Made 11 November 2026 (Session 21, ADO 2549), at Boroon's word. Plan 8.3 point 4 says to record each third-party skill's source and licence in the component register (plan 8.2). Until now the register was only the class table in the plan. This file holds the rows.

- **What goes here:** one row per third-party source we copy or pin, at its pin. The three skill sources, and since 26 November 2026 (A1's first pass, ADO 2740, Session 56) every kit we pin: Spec Kit, pac, Copilot CLI, the Dataverse CLI, Microsoft's Playwright toolkit, Playwright, axe-core, `playwright-ms-auth` and the kit's other packages, Microsoft's two skill plugin repos, and the GitHub Actions in `factory-gates`; since the same day (Session 57) also the gate's Python test packages. One file serves both plan 8.3 and A1.
- **What does not:** the class of each part of the factory (shipped primitive, thin glue, IP) stays in plan 8.2's table. The detail of each skill (what it became, where its notes are) stays in `skills/README.md`. Nothing here may name a client, a person or an engagement (public repo).
- **Review:** monthly, with the plan 8.2 review, and after each Microsoft or GitHub event. At each pass: check each source for changes since its pin, and update "Last checked". For each update due, read its release notes in full and write down what changes for us. **No pin moves in this file alone:** every update moves by a reviewed pull request in the repo that holds the pin (plan 8.3, rule 17), and this row changes in the same round.

### What changes for us, for each update due

**Spec Kit 1.4.4 and 1.4.5** (changelog read in full, and the code diff for presets, extensions, bundles and the Copilot integration):
- Bug fixes only: 41 commits. Nothing changes in the core templates, in the commands our presets override (`specify`, `clarify`, `plan`, `implement`), or in the packaged `assess` and `bug` extensions.
- Our presets, extension and bundle accept `>=1.4.3,<1.5`, so both install unchanged.
- Useful to us: `specify preset resolve` now says when a project override hides a preset layer, which helps check that `getai-lcp` composes on `getai`; command files with a UTF-8 byte order mark now parse; Windows UTF-8 fixes.
- The Copilot integration now drops hook output on `userPromptSubmitted`. Our `before_implement` hook is Spec Kit's own hook, not a Copilot event, so it is not affected.
- A move re-runs DG4's install check (`specify extension add --dev` and the hook's script path) and DG5's spec check fixtures.

**pac 2.5 to 2.16.1** (NuGet's notes read in full; they list minor versions, and 2.16.1 is the only patch line):

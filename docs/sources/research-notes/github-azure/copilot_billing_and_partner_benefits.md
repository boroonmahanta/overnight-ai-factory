## Key question 1: How is Copilot usage metered and priced today, and what does one coding agent task cost in credits by model?

### Takeaway
Since 1 June 2026 every Copilot plan bills chat, agents, code review, CLI, Spark and third-party agents in GitHub AI Credits (1 credit = USD 0.01), converted from input, cached and output tokens at per-model list rates; there is no longer a flat per-session charge for the coding agent, so one agent task costs whatever its tokens cost on the chosen model, which spans roughly two orders of magnitude between the cheapest lightweight model (GPT-6 Luna, USD 0.10 per 1M input) and the dearest frontier models (GPT-6 Astra and Claude Fable 5.1, USD 10 per 1M input, USD 50 per 1M output). GitHub publishes an official per-task range only for code review (USD 0.05 to 1 per review on Lite, USD 0.25 to 5 on Balanced); it publishes no per-session figure for the cloud (coding) agent.

### Inferences
- Because there is no per-session flat fee any more, the cost of one coding agent task is dominated by (a) how much repository context the agent reads (input tokens, much of it cache hits on re-reads) and (b) the model's output price. Using GitHub's published rates, an illustrative single session that consumes 1.5M input tokens (80% served from cache) and 30K output tokens would cost approximately: GPT-6 Luna USD 0.06 (6 credits); Claude Haiku 5.5 about USD 0.06 for prompts under 100K; Claude Sonnet 5.5 or GPT-6.1 Sol about USD 1.0 (100 credits); GPT-5.3-Codex about USD 1.16 (116 credits); Claude Opus 5.5 about USD 2.0 (204 credits); Claude Fable 5.1 about USD 4.8 (480 credits); GPT-6 Astra about USD 5.7 (570 credits). These exclude cache-write charges (Anthropic and GPT-5.6/6 models) and Actions minutes. The token profile is an assumption, not a GitHub figure, but the ratios between models are exact from the rate table.
- The official code-review range (5 to 500 credits per review) is the best published anchor for "one agentic PR-sized job"; an implementation task that writes code is likely to sit at or above the Balanced review range on the same model class because it reads similar context and generates far more output.
- Model choice is therefore the single largest lever: switching a factory's default from a frontier model (Fable 5.1, GPT-6 Astra) to a "Versatile" model (Sonnet 5.5, GPT-6.1 Sol, GPT-5.6 Terra) cuts per-task credit cost by roughly 5x, and to a "Lightweight" model by roughly 50 to 100x, at the cost of capability.
- For third-party agents (Claude agent, Codex agent) in Agent HQ the current docs say they draw on the same included Actions minutes and AI credits; the specific per-model rate applied to those sessions is not published separately, so the safest assumption is the underlying model's row in the GitHub rate table.

### Gaps
- GitHub publishes no per-session or per-task credit estimate for the cloud (coding) agent, Copilot CLI or third-party agents; only code review has an official range.
- The GitHub Blog announcement and the June 2026 changelog could not be read directly (domain blocked); their contents are reported from search summaries.
- I could not confirm whether the "auto" model selection carries a discount or which model code review uses (GitHub states it is undisclosed).
- Whether Spark consumption is metered per token or has any flat component was not found.

## Key question 2: Which parts of the night would be covered by included allowances, and which would be metered overage?

### Takeaway
Included allowances are three separate monthly pools that reset on the 1st: Copilot AI credits (1,900 per Business seat, 3,900 per Enterprise seat, pooled across the billing entity), GitHub Actions minutes on standard runners (50,000 per month on GitHub Enterprise, 3,000 on Team, 2,000 on Free, private repos) and storage; everything beyond those is metered at USD 0.01 per credit and the published per-minute runner rates, and additional AI-credit usage is enabled by default unless an admin turns off the "AI credits paid usage" policy or sets hard-stop budgets.

### Cited Findings
- Each assigned Business or Enterprise licence adds its monthly credits to a shared pool; usage beyond the pool is charged per credit; code completions and next edit suggestions are not billed in credits. — [GitHub Docs source, seats and billing cycles](https://raw.githubusercontent.com/github/docs/main/content/copilot/concepts/billing-and-usage/organizations-and-enterprises/seats-and-billing-cycles.md)
- Standard included credits: Business 1,900 and Enterprise 3,900 per user per month (promotional 3,000 and 7,000 ended 1 September 2026). — [GitHub Docs source, variables](https://raw.githubusercontent.com/github/docs/main/data/variables/copilot.yml); [GitHub Docs, usage-based billing](https://docs.github.com/en/copilot/concepts/billing/usage-based-billing-for-organizations-and-enterprises) [snippet]
- Overage behaviour: additional usage is enabled by default; an administrator can turn off the "AI credits paid usage" policy in AI Controls to block spending beyond included credits; if the pool is exhausted and overage is allowed, usage continues at published per-credit rates charged to the organisation or enterprise, and if a spend cap is hit the consumed overage must be paid before usage continues; if overage is not allowed, usage is blocked until the next monthly refresh. — [GitHub Docs source, usage-based billing for organisations and enterprises](https://raw.githubusercontent.com/github/docs/main/content/copilot/concepts/billing-and-usage/organizations-and-enterprises/billing.md)
- Budgets: types are product-level, SKU-level and "bundled AI credits" (all SKUs that consume AI credits); enterprise AI-credit budgets can be scoped to the whole enterprise, an organisation, a cost centre or individual users; user-level budgets can be universal (per-user amount for all licensed users), per cost centre, or individual, and always hard-stop; user-level budgets are evaluated first so they can block a user even when the enterprise pool has room; alerts fire at 75%, 90% and 100%; separate included-usage alerts at 90% and 100%; premium request budgets were converted automatically to AI credit budgets; "included usage controls" can cap how much of the shared pool a cost centre uses before metered billing applies; when an Actions product budget with hard stop is exhausted, members lose GitHub-hosted runners until the next cycle. — [GitHub Docs source, set up budgets](https://raw.githubusercontent.com/github/docs/main/content/billing/how-tos/set-up-budgets.md) (rendered: https://docs.github.com/en/billing/how-tos/set-up-budgets)

- GitHub-hosted runner per-minute rates (USD): x64 Linux 2-core "advanced" 0.006, 4-core 0.012, 8-core 0.022, 16-core 0.042, 32-core 0.082, 64-core 0.162, 96-core 0.252; x64 Windows 4-core 0.022 up to 96-core 0.552; arm64 Linux 2-core 0.005, 4-core 0.008; x64 macOS 12-core 0.077; GPU Linux 4-core 0.052; each job's minutes are rounded up to the nearest whole minute; included minutes cannot be used for larger runners. — [GitHub Docs source, Actions runner pricing](https://raw.githubusercontent.com/github/docs/main/content/billing/reference/actions-runner-pricing.md) (rendered: https://docs.github.com/en/billing/reference/actions-runner-pricing)
- Code review consumes both AI credits and GitHub Actions minutes for agentic context gathering and tool use; the cloud agent runs on GitHub Actions so its minutes vary with task length. [snippet] — [GitHub Docs, code review](https://docs.github.com/en/copilot/concepts/agents/code-review); [GitHub Changelog, July 2025](https://github.blog/changelog/2025-07-10-github-copilot-coding-agent-now-uses-one-premium-request-per-session/)
- Third-party agents in Agent HQ: "within your included GitHub Actions minutes and AI credits, you can use agents without incurring additional costs". [snippet] — [GitHub Docs, about third-party coding agents](https://docs.github.com/en/copilot/concepts/agents/about-third-party-coding-agents)
- A GitHub App's Copilot usage bills to the installing organisation under its policies, and budgets cannot be set per app or installation. — [GitHub Docs source, usage-based billing for organisations and enterprises](https://raw.githubusercontent.com/github/docs/main/content/copilot/concepts/billing-and-usage/organizations-and-enterprises/billing.md)

### Inferences
- Worked sizing: a factory with 10 Copilot Enterprise seats has 39,000 pooled credits (USD 390) per month, or about 1,300 credits (USD 13) per night over 30 nights. At the illustrative 100 to 500 credits per agent session on a Versatile-to-frontier model, that covers roughly 3 to 13 agent sessions per night before overage; at 5 to 10 credits per session on a Lightweight model it covers more than 100. With 10 Business seats the pool halves (19,000 credits, USD 190 per month).
- Actions is the more generous pool: 50,000 included minutes on GitHub Enterprise is about 1,660 minutes per night, so roughly 100 fifteen-minute agent sessions per night on standard runners before Actions overage; a Team plan's 3,000 minutes (100 per night) would be exhausted by a handful of sessions. Only standard-runner minutes are included; any larger runner is metered from the first minute.
- Code review on every PR the agents open is a second credit drain: at the official Balanced range, 20 reviews per night is USD 5 to 100 per night (500 to 10,000 credits), which on its own can exceed the nightly share of the pool. Setting the default effort to Lite, or reviewing only on request, is a direct lever.
- Because additional usage is on by default, an unattended night will silently run into overage unless the factory sets (a) an enterprise or cost-centre AI-credit budget with "stop usage" and (b) an Actions product budget, accepting that hard-stop budgets will halt agents mid-night.
- Seats themselves are a fixed cost (USD 19 or 39 per assigned seat per month) that no included allowance offsets; every service identity that triggers agent work must hold a seat.

### Gaps
- The standard 2-core Linux runner's current per-minute price was not confirmed; the fetched page listed a "2-core advanced" x64 Linux runner at USD 0.006 but the summary did not show a plain standard-runner row. The macOS and Windows minute multipliers for included minutes were not on the page as read.
- Whether code completions used by agents (not humans) are ever metered was not addressed in the sources.
- The default spend cap value, if any, for overage on a brand-new enterprise was not stated.

## Key question 3: Can overage be billed to the Azure subscription, and would Microsoft partner Azure credits pay for it?

### Takeaway
Yes, Copilot licences and usage beyond the included AI-credit pool, together with Actions, Codespaces, Packages, LFS, GitHub Enterprise and GitHub Advanced Security, can be billed through an Azure subscription connected to the GitHub organisation or enterprise (usage is sent to Azure daily and invoiced the following month, appearing per SKU and per enterprise or cost centre, and is MACC-eligible). Partner Azure credits are explicitly designed to be used this way (the Solutions Partner Azure designations include "GitHub Copilot Enterprise (via Azure credits)" and Azure specialisations add "GitHub Enterprise Metered (via Azure credits)"), and general Azure credits cover first-party Azure consumption, which GitHub meters are, but the documentation never walks through the GitHub side for partner credits and GitHub lists several Azure offer types it will not accept, so the eligibility of the specific subscription type the credits land on remains the unresolved point.

- GitHub (Azure subscription reference): there is no limit to the number of enterprises or cost centres connected to one Azure subscription; to use multiple Azure subscriptions for one enterprise, create cost centres and connect each to a different subscription; usage from a cost centre without a subscription falls back to the enterprise's subscription; on the Azure invoice GitHub usage is summarised by product family and separated by SKU and by enterprise ID or cost centre ID in the format `enterprise:sku` or `costcenter:sku` (internal IDs, hard to match); example line items include GH ENTERPRISE and GH ADVANCED SECURITY; GitHub products on the Azure invoice are MACC-eligible; during an EMU trial, exceeding included limits requires linking an Azure subscription, and connecting one to a non-EMU GHEC trial ends the trial immediately. — [GitHub Docs source, Azure subscription reference](https://raw.githubusercontent.com/github/docs/main/content/billing/reference/azure-subscription.md) (rendered: https://docs.github.com/en/billing/reference/azure-subscription)

## Key question 4: What is the finest grain at which GitHub reports Copilot and Actions spend, and what is missing for a per-agent, per-night, per-project ledger?

### Takeaway
GitHub exposes daily, per-SKU, per-organisation, per-repository, per-cost-centre, per-user (detailed report) and, for AI credits, per-model and per-user token-level data through the enhanced billing platform's usage reports and REST endpoints (`/enterprises/{enterprise}/settings/billing/usage`, `/usage/summary`, `/ai_credit/usage`, plus budgets and cost-centre APIs), and the Copilot usage metrics API adds per-user daily feature flags, per-model and per-feature totals and a non-invoicing `ai_credits_used`; what is missing is any session, task, issue or pull request identifier on billing rows, any repository dimension on AI-credit rows (credits are attributed to the triggering user, Actions to the repository), hourly granularity (removed in June 2026) and a published lag figure, so a per-agent per-project ledger has to be built by mapping service identities and cost centres to projects and joining to Actions workflow rows.

### Cited Findings
- Report types and granularity: summarised usage report (metered usage page, up to 1 year) by date, SKU, repository, cost centre and organisation; detailed usage report (31 days max) by date, SKU, organisation, repository, cost centre, user and workflow path; AI usage report (AI usage page, 31 days max) by date, model and user with a token breakdown per model. Common fields: `date` (UTC), `product`, `sku`, `quantity`, `unit_type`, `applied_cost_per_quantity`, `gross_amount`, `discount_amount`, `net_amount`, `repository`, `cost_center_name`, `organization`; detailed report adds `workflow_path`; `username` is not in the summarised report; AI usage report adds `model`, `input`, `output`, `cache_read`, `cache_write`, `app_client_id`; `gross_amount - discount_amount = net_amount` where `discount_amount` includes usage covered by included allowances; reports are emailed and only one can be requested per account at a time; `usage_at` was replaced by `date` and `workflow_name` by `workflow_path`. — [GitHub Docs source, billing reports](https://raw.githubusercontent.com/github/docs/main/content/billing/reference/billing-reports.md) (rendered: https://docs.github.com/en/billing/reference/billing-reports)
- REST billing API areas: billing, budgets, cost-centers, usage, usage-reports (usage reports: "create and retrieve usage report exports for an enterprise", GHEC only). User-level usage endpoints only cover Copilot bought personally; licences managed by an organisation or enterprise appear in the organisation or enterprise endpoints. — [GitHub Docs source, REST billing index](https://raw.githubusercontent.com/github/docs/main/content/rest/billing/index.md) and [REST billing usage](https://raw.githubusercontent.com/github/docs/main/content/rest/billing/usage.md) (rendered: https://docs.github.com/en/enterprise-cloud@latest/rest/billing)
- Automating usage reporting: enterprise usage summary at `/enterprises/{enterprise}/settings/billing/usage/summary` with equivalent organisation and user endpoints; filters `year`, `month`, `day`, `hour` (defaults to current year); `cost_center_id` filters enterprise summaries; `quantity` is the amount consumed by unit type, `netAmount` the billed cost, `discountAmount` usage covered by included quotas or discounts; the AI usage endpoint reports consumption by model; billing endpoints require a personal access token (classic) with billing permissions and do not support fine-grained PATs; a GitHub App installation token with enterprise billing read permission can be used and expires after one hour. — [GitHub Docs source, automate usage reporting](https://raw.githubusercontent.com/github/docs/main/content/billing/tutorials/automate-usage-reporting.md) (rendered: https://docs.github.com/en/billing/tutorials/automate-usage-reporting)
- The AI credit usage endpoints are `/enterprises/{enterprise}/settings/billing/ai_credit/usage` and `/organizations/{org}/settings/billing/ai_credit/usage` (enterprise version restricted to administrators or billing managers, supports per-user filtering, data for the past 24 months); the sample response has per-item fields such as model, unit type, gross and net quantity and amounts, with units in credits; a June 2026 changelog added a Usage summary API and removed the `hour` parameter from the usage report, switching `day` queries to daily totals. [snippet] — [DX connector guide](https://docs.getdx.com/connectors/github-copilot-billing.md); [GitHub Changelog, 4 June 2026, Budget and usage management APIs GA](https://github.blog/changelog/2026-06-04-budget-and-usage-management-apis-now-generally-available); the older premium-request usage endpoint response showed `product`, `sku`, `model`, `unitType`, `pricePerUnit`, `grossQuantity`, `grossAmount`, `discountQuantity`, `discountAmount`, `netQuantity`, `netAmount`. [snippet] — [GitHub Docs REST billing usage](https://docs.github.com/en/enterprise-cloud@latest/rest/billing/usage)
- Cost-centre allocation rules: Actions to the repository or organisation where the workflow runs; Codespaces to the repository or organisation where created; Copilot licences and GHE licences to the user who holds the licence, else the billing organisation; AI credits to the user who triggered the usage, else the organisation that granted the licence; GHAS to the user, else the organisation; a user can be in only one cost centre for licensing (direct assignment beats enterprise team, earliest-created team wins conflicts); users in multiple organisations have Copilot usage allocated to one of the organisations' cost centres; unallocated usage shows as "Enterprise Only"; future usage falls to the enterprise if a user is removed from a cost centre or the cost centre is deleted. — [GitHub Docs source, cost centre allocation](https://raw.githubusercontent.com/github/docs/main/content/billing/reference/cost-center-allocation.md) (rendered: https://docs.github.com/en/billing/reference/cost-center-allocation)
- Copilot usage metrics (not billing): enterprise and organisation scope at aggregated, repository or per-user granularity; per-user 1-day and 28-day reports include `user_id`, `user_login`, `day`, interaction and code acceptance counts, flags `used_agent`, `used_chat`, `used_cli`, `used_copilot_app`, cloud agent, code review (active and passive), `ai_credits_used` ("for consumption analysis and not invoicing"), `ai_adoption_phase`, and customisation counts (skills, custom agents, MCP servers, slash commands, plugins); `totals_by_feature` values include `code_completion`, `chat_inline`, chat panel modes, `agent_edit`, `copilot_cli`, `copilot_app`; `totals_by_model_feature` covers chat activity only (model IDs, `auto`, `unknown`, `others`); `totals_by_ide`; a `pull_requests` object with daily created, reviewed, merged and suggested counts including cloud agent and code review; repository reports (`*-repos-1-day`) have one record per repository with PR activity that day; user-teams reports exclude teams with fewer than 5 seated users; dashboards do not include Copilot CLI usage; PR review-time data excludes PRs ready for review before 21 September 2026. — [GitHub Docs source, Copilot usage metrics data](https://raw.githubusercontent.com/github/docs/main/content/copilot/reference/copilot-usage-metrics/copilot-usage-metrics.md) (rendered: https://docs.github.com/en/copilot/reference/copilot-usage-metrics/copilot-usage-metrics)

- CLI and SDK sessions can carry an AI credit session limit (July 2026), implying per-session credit accounting exists inside those surfaces. [snippet] — [GitHub Changelog, 1 July 2026](https://github.blog/changelog/2026-07-01-set-ai-credit-session-limits-in-copilot-cli-and-sdk/)

### Inferences
- The finest documented grains are: AI credits by day x model x user (with input, output, cache_read, cache_write token counts); Actions by day x SKU x organisation x repository x cost centre x user x workflow_path; both with gross, discount and net amounts. Nothing is keyed by session, task, issue, PR or run ID.
- Because AI credits follow the triggering user, a factory can make "project" visible in billing by giving each project (or each agent persona) its own seated service identity and assigning that identity to a project cost centre; the AI usage report then yields per-project, per-model, per-day credits, and the Actions detailed report yields per-repository, per-workflow minutes. Human developers' daytime usage stays separable because it sits under their own logins.
- A per-night view is achievable only at day granularity (UTC) now that the hour parameter has been removed; a night that straddles midnight UTC will split across two rows.
- To get per-run attribution, the factory needs its own ledger: record each agent dispatch (issue or PR, model, start and end time, identity) and reconcile it against the daily per-user per-model credit totals and the per-workflow Actions rows; the `ai_credits_used` metric and the pull_requests object in the metrics API can act as a cross-check but are explicitly not invoicing data.
- Data lag is not published for the billing reports; the only official figures are "daily" for the metrics reports and for the GitHub-to-Azure feed, and 48 hours for the Azure DevOps Copilot code review meter, so a morning-after ledger should expect same-day data to be incomplete.

### Gaps
- No official statement of the billing usage API's data lag, rate limits or retention beyond the 24-month figure for AI credit usage (which came from a third-party connector guide).
- Whether the enterprise usage endpoint response includes `repositoryName`, `organizationName` and `costCenter` fields was not confirmed from a page read in this session; the field list above comes from the CSV report reference and search snippets of the REST reference.
- Whether cloud-agent sessions are attributed to the human who assigned the issue, to the Copilot bot, or to a GitHub App identity in the AI usage report was not stated; the "app_client_id" field in the AI usage report suggests app-originated usage is distinguishable.
- Whether the Copilot SDK exposes per-session credit totals programmatically was not confirmed.

- PTU sizing: for gpt-5 one output token counts as eight input tokens toward utilisation (matching the price ratio), for gpt-4.1 four; cached tokens are deducted 100% from utilisation for models without normalised token accounting, whereas GPT-6 Astra, GPT-6 Sol and GPT-6.1 Sol consume PTU capacity for cached tokens at model-specific weights; long-context requests over 128K are not supported on gpt-5.4 and gpt-4.1 PTU and spill over. — [Microsoft Learn, PTU sizing](https://learn.microsoft.com/azure/foundry/openai/how-to/provisioned-throughput-sizing)
- Prompt caching: "cached tokens are billed at a discount on input token pricing for Standard deployment types and up to 100% discount on input tokens for Provisioned deployment types"; caches clear within 5 to 10 minutes of inactivity and always within one hour; caches are not shared between Azure subscriptions. — [Microsoft Learn, prompt caching](https://learn.microsoft.com/azure/ai-foundry/openai/how-to/prompt-caching)
- Credit eligibility of models: "Startup credits apply to Microsoft Foundry models that are sold and billed directly by Azure. Models billed by third-party providers (including Anthropic), partner services, or available through the Microsoft Marketplace are not eligible"; use the "Direct from Azure" collection to identify eligible models; Anthropic, Cohere (select), Hugging Face, Meta (select) and Mistral (select) are not covered. — [Microsoft Learn, Microsoft for Startups credit coverage for Foundry models](https://learn.microsoft.com/en-us/microsoft-for-startups/build/foundry-model-sponsorship-coverage); the MCA credits page makes the same distinction for Azure Sponsorship credits generally. — [Microsoft Learn, MCA credits](https://learn.microsoft.com/azure/cost-management-billing/benefits/credits/mca-check-azure-credits-balance)
- Claude in Foundry billing: all Claude models bill in Claude Consumption Units (CCU); token usage is priced at Anthropic's per-model rates, discounts (Azure Marketplace private offers) applied, then converted at the fixed CCU price; metered hourly to Azure Marketplace, invoiced monthly in arrears, no prepaid CCU; MACC-eligible; Cost Management shows a single CCU line with per-model token detail only in the Foundry portal Monitor tab; Claude models are "Non-Microsoft Products under the Product Terms" accessed through "Foundry Models from partners and community"; two hosting versions exist (Anthropic-hosted and Azure-hosted). — [Microsoft Learn, CCU billing](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/claude-models-billing); [Claude models in Foundry](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/claude-models)

- Claude in Foundry subscription requirements: a paid Azure subscription with a billing account in a supported country; not supported are CSP subscriptions, subscriptions without an active pay-as-you-go billing method (student, free trial, startup credit-based), and "Sponsored subscriptions that only use Azure credits. ### Inferences
- An "on Azure credits" path for the factory's own orchestrator or non-Copilot agents is viable only with Azure OpenAI (or other Direct-from-Azure) models; Claude via Foundry will consume MACC but not partner credits and needs a card or invoice billing method, so a partner wanting Claude on credits has none, and a partner wanting Claude at all should expect it to be billed outside the credit pool.
- At list prices, GPT-5.3-Codex on Azure (USD 1.75 / 0.175 / 14) is cheaper per token than Claude Sonnet 5.5 on input but 40% dearer on output, and the GitHub Copilot rate for the same model is identical, so routing an agent through Copilot versus directly through Azure OpenAI changes who pays (Copilot credits versus Azure credits) rather than the per-token price, with Copilot adding included credits and Azure adding the possibility of PTU and 100% cache discounts.
- The 10,000 USD per year Solutions Partner bulk credit equates, at GPT-5.3-Codex list rates and the illustrative 1.5M-input (80% cached) and 30K-output session profile (about USD 1.16), to roughly 8,600 such sessions per year or about 24 per night; with Lightweight models (GPT-6 Luna) it is two orders of magnitude more.

### Gaps
- The official Azure OpenAI pricing page (azure.microsoft.com) was blocked; the per-token figures are from aggregators marked [snippet] and from GitHub's rate table as a proxy; PTU hourly prices, Batch discounts and the Data Zone and Regional uplifts for GPT-5.4 and later were not obtained.
- Azure-side list prices for the GPT-5.6 and GPT-6 series were not found on any reachable page; only the Copilot rate table shows them.
- Whether Azure OpenAI Global Standard prices in Australian regions carry any regional uplift was not checked.

# Azure infrastructure for an overnight autonomous software factory (as of 24 October 2026)

Scope: Azure services for each layer of a nightly agent factory (sandbox, model, orchestration, CI, telemetry, reporting), what each costs, how to attribute cost per project and per run, the traps, and what Azure credits do and do not cover. Workers may be GitHub Copilot agents, Claude Code, Codex CLI or custom agents.

Dating and sourcing conventions used below:
- "[24 Oct 2026]" means the page was retrieved in full on 24 October 2026 from Microsoft Learn, platform.claude.com or code.claude.com and reflects that date.
- "[snippet]" means only a web-search summary was available (azure.microsoft.com pricing pages, prices.azure.com and docs.github.com were unreachable from the research sandbox). Treat those numbers as indicative and re-verify in the Azure pricing calculator or GitHub docs before budgeting.
- "[assumption]" marks planning numbers that are not from any source; they exist only to make the arithmetic concrete.
- Naming: Azure AI Foundry was renamed Microsoft Foundry during 2025 and 2026. Learn now has a "Foundry (new)" doc set under learn.microsoft.com/azure/foundry and a "Foundry (classic)" set under learn.microsoft.com/azure/foundry-classic. Older URLs under /azure/ai-foundry still resolve. "Azure OpenAI in Microsoft Foundry Models" is the current product name for what was Azure OpenAI Service. The RBAC role "Azure AI User" is now "Foundry User".

## Key question 1: Which Azure services fit each layer, and what does a small factory (3 to 4 concurrent workers, 8 hours a night, 20 nights a month) cost per month?

### Takeaway
Pick Azure Container Apps jobs (Consumption plan, workload-profiles environment) as the sandbox and self-hosted CI runner, Microsoft Foundry for models (Azure OpenAI GPT-5.x/Codex when you want credits to pay; Claude via Foundry when you want Claude but accept Marketplace billing), Durable Functions or the Durable Task SDK on the Durable Task Scheduler Consumption SKU for the nightly loop with human-approval gates, Application Insights with OTLP ingestion plus Log Analytics for telemetry, and Cost Management exports (FOCUS) into Power BI or a FinOps hub for the profitability matrix. Infrastructure for 480 to 640 worker-hours a month is roughly US$110 to US$160 (compute dominates, and the compute unit price could not be verified from this sandbox); model tokens dominate the bill and range from under US$1,000 to several thousand dollars a month depending on model and token volume, so measure with Claude Code's `claude_code.cost.usage` before committing.

### Cited Findings

#### Layer 1: Sandbox and worker compute

Azure Container Apps (ACA) jobs
- Jobs "run for a finite duration and then stop"; trigger types are Manual, Schedule (cron, evaluated in UTC) and Event (KEDA scalers such as Azure Storage queue, Service Bus, Kafka, RabbitMQ, GitHub Actions runner scale rule). [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs)
- A self-hosted GitHub Actions runner is an explicitly documented job scenario: "Use the Event job type and configure a GitHub Actions ... scale rule." [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs)
- Job settings: `replicaTimeout` ("maximum time in seconds to wait for a replica to complete"), `replicaRetryLimit`, `parallelism`, `replicaCompletionCount`, `pollingInterval` (default 30 s). The ARM/CLI examples and the Bicep AVM module default `replicaTimeout` to 1800 seconds. No documented upper bound for `replicaTimeout` was found (see Gaps). [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs); [Container App Jobs Bicep module README](https://raw.githubusercontent.com/Azure/bicep-registry-modules/refs/heads/main/avm/res/app/job/README.md)
- Long-running jobs warning: "Platform maintenance, including routine security updates and upgrades, might interrupt long-running job replicas. Set the replica retry limit to at least 1, and design your workload for at-least-once processing." [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs)
- Execution history is limited to the most recent 100 successful and failed executions for scheduled and event jobs; use the environment's log provider for a full record. [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs)
- Restrictions: jobs do not support Dapr, ingress, custom domains or SSL certificates. [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs)
- Permissions trap: "Permission to start a job can provide access to that job's secrets even when the role doesn't include the listSecrets action", because the Start API accepts an execution template that can override images, commands and environment variables and reference secrets by name. Grant `Microsoft.App/jobs/start/action` only to trusted identities. [24 Oct 2026] [Jobs in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/jobs)
- Runner tutorial constraints: "Container apps and jobs don't support running Docker in containers. Any steps in your workflows that use Docker commands fail when run on a self-hosted runner or agent in a Container Apps job." Self-hosted runners are recommended only for private repositories. The runner job evaluates the scale rule every 30 s and starts one execution per pending workflow run, up to a configured maximum (10 in the tutorial). [24 Oct 2026] [Tutorial: self-hosted CI/CD runners with Container Apps jobs](https://learn.microsoft.com/azure/container-apps/tutorial-ci-cd-runners-jobs)
- Consumption-plan billing: vCPU-seconds and GiB-seconds "allocated to your container app on a per-second basis"; first 180,000 vCPU-seconds, 360,000 GiB-seconds and 2 million HTTP requests per subscription per calendar month are free; jobs are always charged at the active rate ("Idle charges don't apply to jobs"); request charges don't apply to jobs. The managed OpenTelemetry agent runs at no extra compute cost. Consumption workload profile supports container images up to 8 GB per replica. [24 Oct 2026] [Billing in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/billing); [Containers in Azure Container Apps](https://learn.microsoft.com/azure/container-apps/containers)
- Unit prices: the official pricing page renders placeholders in search results; a China-region page lists active vCPU at ¥0.00024 per second and memory at ¥0.000031 per GiB-second (CNY, not transferable to USD). No verified USD per-second rate was obtained. [snippet] [Azure Container Apps pricing](https://azure.microsoft.com/en-us/pricing/details/container-apps/); [Azure China Container Apps pricing](https://www.azure.cn/en-us/pricing/details/container-apps/)
- Networking: use a workload-profiles environment (the default) if you need user-defined routes, egress via NAT Gateway, Azure Firewall or private endpoints; minimum subnet /27. The legacy Consumption-only environment supports none of those (minimum /23). [24 Oct 2026] [Networking in an Azure Container Apps environment](https://learn.microsoft.com/azure/container-apps/networking)

ACA dynamic sessions (code interpreter and custom container)
- Dynamic sessions are "Hyper-V isolation" sandboxes allocated from pre-warmed pools in milliseconds; "By default, sessions are prevented from making outbound network requests" and egress can be enabled per pool (with a warning about untrusted code). Pool management API auth is Entra tokens with the "Azure ContainerApps Session Executor" role. Managed identity can be exposed to the session (`managedIdentitySettings.lifecycle`: `None` default, `Main` "use with caution"). [24 Oct 2026] [Dynamic sessions](https://learn.microsoft.com/azure/container-apps/sessions); [Use dynamic sessions](https://learn.microsoft.com/azure/container-apps/sessions-usage); [Session pools](https://learn.microsoft.com/azure/container-apps/session-pool)
- Billing: code interpreter sessions are billed per allocated session in increments of one hour; custom container sessions are billed on the Dedicated plan and "Each custom container session pool runs on dedicated E16 compute instances", with instance count driven by active and ready sessions. [24 Oct 2026] [Billing in Azure Container Apps: dynamic sessions](https://learn.microsoft.com/azure/container-apps/billing#dynamic-sessions)
- Regions include East US 2, Sweden Central, Australia East and Australia Southeast among many others. [24 Oct 2026] [Dynamic sessions: supported regions](https://learn.microsoft.com/azure/container-apps/sessions#supported-regions)
- A Microsoft sample runs Microsoft Agent Framework against a custom-container session pool using managed identity, with Bicep parameters `maxConcurrentSessions` (default 10) and `readySessionInstances` (default 5), and a two-step azd deploy because the pool needs the image in ACR first. [24 Oct 2026] [Azure-Samples/dynamic-sessions-custom-container](https://raw.githubusercontent.com/Azure-Samples/dynamic-sessions-custom-container/refs/heads/main/README.md)

Azure Container Instances (ACI)
- ACI Spot containers (preview) offer "up to 70% discounted prices vs regular-priority ACI containers", can be pre-empted, default quota 10 vCPU and 10 container groups, and do not support public IP or private VNet deployments. Confidential containers cost extra. [24 Oct 2026] [ACI FAQ](https://learn.microsoft.com/azure/container-instances/container-instances-faq)
- No ACI per-vCPU-second USD price was verifiable from this sandbox (see Gaps).

AKS with Actions Runner Controller (ARC)
- Microsoft documents a reference architecture for ARC on AKS with Azure Files (SMB) shares for NuGet caching, namespaces `arc-controller` and `arc-runners`, GitHub App credentials in Kubernetes secrets, ephemeral runner pods destroyed after each job. ARC itself is open source and "excluded from AKS service-level agreements, limited warranty, and Azure support". [24 Oct 2026] [GitHub Actions on AKS using Azure Files overview](https://learn.microsoft.com/azure/aks/github-actions-azure-files-overview); [Create the infrastructure](https://learn.microsoft.com/azure/aks/github-actions-azure-files-create-infrastructure)
- AKS cost is node VM cost plus managed disks; "The longer that agent nodes are operational, the higher the total cluster cost. Development environments don't usually need to run continuously." [24 Oct 2026] [Cost management for Kubernetes](https://learn.microsoft.com/azure/architecture/aws-professional/eks-to-aks/cost-management)

Microsoft Dev Box
- Pricing model per the official page: monthly storage fee per box plus hourly compute while active, capped at a max monthly price per instance; numbers render as placeholders. Third-party figures conflict (about US$0.30/hour for 8 vCPU/32 GB per one 2026 blog versus US$1.98/hour in an older article). [snippet] [Dev Box pricing](https://azure.microsoft.com/pricing/details/dev-box); [microsoftnegotiations.com](https://microsoftnegotiations.com/blog/microsoft-dev-home-licensing); [codeguru.com](https://www.codeguru.com/tools/microsoft-dev-box/)
- Dev Box is a developer-workstation product (dev centers, projects, pools, image definitions, network connections); nothing in the deployment guide positions it for headless agent workers. [24 Oct 2026] [Dev Box deployment guide](https://learn.microsoft.com/azure/dev-box/concept-dev-box-deployment-guide)

GitHub Codespaces (comparison point)
- Compute US$0.18/hour for 2-core, US$0.36 for 4-core, US$0.72 for 8-core, US$1.44 for 16-core, US$2.88 for 32-core; storage US$0.07 per GB-month; storage continues to bill while stopped; organisations do not inherit personal free allowances. Free allowances for personal accounts are reported inconsistently (60 versus 120 core-hours). [snippet] [About Codespaces pricing](https://docs.github.com/en/enterprise-cloud@latest/billing/managing-billing-for-your-products/managing-billing-for-github-codespaces/about-billing-for-github-codespaces); [How Codespaces use is measured](https://docs.github.com/en/billing/concepts/product-billing/github-codespaces)

Foundry Agent Service hosted agents (managed alternative to running your own containers)
- Hosted agents run "your own code packaged as a container image" (Agent Framework, LangGraph, OpenAI Agents SDK, Anthropic Agent SDK, GitHub Copilot SDK or custom) in "per-session VM-isolated sandboxes" with persistent `$HOME`, a dedicated Entra agent identity, autoscale per session, and "scale-to-zero with stateful resume". CPU/memory tiers: 0.5 vCPU/1 GiB, 1 vCPU/2 GiB, 2 vCPU/4 GiB; disk budget up to 20 GiB at 1 vCPU or larger; idle timeout 2 to 240 minutes (default 15); sessions deleted after 30 days idle. "Billing is based on cpu + memory consumed across all active sessions." Available in 31 regions including Australia East, East US 2 and Sweden Central. [24 Oct 2026] [What are hosted agents?](https://learn.microsoft.com/azure/foundry/agents/concepts/hosted-agents); [Agents in Microsoft Foundry](https://learn.microsoft.com/azure/foundry/agents/overview)
- Agent Service charges model inference per call, Code Interpreter per session (sessions active one hour), file search by vector storage; "No" additional quota beyond model quotas. [24 Oct 2026] [Foundry Agent Service FAQ](https://learn.microsoft.com/azure/foundry/agents/faq)
- A preview durable state store gives hosted agents server-backed key-value JSON storage with per-user isolation, optimistic concurrency and configurable expiry (default 30-day idle window). [24 Oct 2026] [Durable state store for hosted agents](https://learn.microsoft.com/azure/foundry/agents/concepts/agent-state-store)

#### Layer 2: Model hosting (Microsoft Foundry)

Catalogue structure
- Foundry Models split into "Foundry Models sold by Azure" and "Foundry Models from partners and community"; partner models "that are not sold by Azure are Non-Microsoft Products", require Azure Marketplace, and need `Microsoft.MarketplaceOrdering/*` and `Microsoft.SaaS/*` permissions (Owner or Contributor on the subscription include them). #### Layer 4: Orchestration

Durable Functions and the Durable Task Scheduler (DTS)
- DTS is "the recommended storage provider for Durable Functions and the Durable Task SDKs"; SDKs let you run durable orchestrations on ACA, AKS, App Service or VMs. Two SKUs: Dedicated (fixed monthly cost per Capacity Unit; up to 2,000 actions/s and 50 GB per CU; up to 3 CUs; 90-day retention; HA needs 3 CUs; 25 schedulers and 25 task hubs per region per subscription) and Consumption (pay per action dispatched; no base fee; 500 actions/s; 30-day retention; no HA; 10 schedulers per region per subscription and 5 task hubs per scheduler). "An action is a message dispatched by the Durable Task Scheduler to your application that triggers the execution of an orchestrator, activity, or entity function." Prices are on the Azure Functions pricing page (not retrievable here; see Gaps). [24 Oct 2026] [Durable Task Scheduler](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler); [DTS billing](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler-billing); [Durable Functions billing](https://learn.microsoft.com/azure/durable-task/durable-functions/durable-functions-billing)
- DTS payload limits: orchestrator and activity inputs/outputs, external event data, custom status and entity state each max 1 MB; each work item completion request max 3.9 MB (large payload support offloads to Blob Storage); instance IDs max 100 printable ASCII characters, `@` prefix reserved. Private endpoints supported on both SKUs; identity-based access (role "Durable Task Data Contributor") still required. [24 Oct 2026] [DTS limitations](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler#limitations-and-considerations); [DTS private endpoints](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler-private-endpoints)
- Human approval pattern: orchestrator notifies an approver, starts a durable timer and waits for an external event; `WhenAny` picks whichever completes first; cancel unneeded timers. External events are one-way, at-least-once (dedupe with unique IDs), discarded if no instance matches; raise them via the orchestration client or the built-in HTTP API `POST /runtime/webhooks/durabletask/instances/{id}/raiseEvent/{eventName}`. "If your function app uses the Consumption Plan, no billing charges are incurred while an orchestrator function is awaiting an external event task, no matter how long it waits." [24 Oct 2026] [Human interaction pattern](https://learn.microsoft.com/azure/durable-task/common/durable-task-human-interaction); [External events](https://learn.microsoft.com/azure/durable-task/common/durable-task-external-events)
- "Support will end for the in-process model on November 10, 2026"; migrate to the isolated worker model. An unhandled orchestrator exception ends the instance as Failed and it cannot be retried. [24 Oct 2026] [External events](https://learn.microsoft.com/azure/durable-task/common/durable-task-external-events); [Durable orchestrations](https://learn.microsoft.com/azure/durable-task/common/durable-task-orchestrations)
- Functions hosting: Flex Consumption bills executions plus GB-seconds while instances actively execute, plus any always-ready instances (no free grants in always-ready mode); minimum billable execution 1,000 ms then 100 ms rounding. The Learn cost article uses example on-demand rates of US$0.000026 per GB-second and US$0.40 per million executions ("Assuming", not a price list). For Durable Functions on Flex Consumption with the Azure Storage provider, set always-ready count for the `durable` group to 1 and reduce queue polling to 10 s or less. [24 Oct 2026] [Estimating consumption-based costs](https://learn.microsoft.com/azure/azure-functions/functions-consumption-costs); [Flex Consumption plan](https://learn.microsoft.com/azure/azure-functions/flex-consumption-plan); [Azure Storage provider](https://learn.microsoft.com/azure/durable-task/durable-functions/durable-functions-azure-storage-provider)
- Hosting model choice: Durable Functions (Functions-managed scale, built-in triggers, DTS/Azure Storage/MSSQL/Netherite state) versus standalone Durable Task SDKs (any platform, you manage scaling, DTS state only, Go beta). [24 Oct 2026] [Choose your Durable Task hosting model](https://learn.microsoft.com/azure/durable-task/common/choose-orchestration-framework)

### Inferences (recommended stack and monthly cost for the small factory)

Working size: 3 to 4 workers x 8 h x 20 nights = 480 to 640 worker-hours per month.

Recommended picks per layer
- Sandbox and CI: ACA jobs on the Consumption plan in a workload-profiles environment, one job definition per worker type (Claude Code, Codex CLI, custom agent) and one event-driven job acting as the GitHub Actions runner. Reasons: per-second billing with scale to zero, no idle cost between nights, retries, KEDA triggers, VNet egress control, managed identity to Foundry, Key Vault and the DTS. Avoid custom-container dynamic sessions for this size because the pool runs on dedicated E16 instances. Use AKS plus ARC only if you need Docker-in-Docker (ACA jobs cannot run Docker) or very long single runs.
- Model: Azure OpenAI GPT-5.x or Codex deployments (Global Standard) when credits must pay; Claude Sonnet 5.5 or Opus 5.5 "Hosted on Azure" Global Standard deployments in East US 2 (or Sweden Central) when you want Claude, accepting Marketplace billing and the 40 RPM / 40K ITPM / 8K OTPM pay-as-you-go defaults until a quota increase is approved. Put each project behind its own Foundry resource (or at least its own deployment name) so Cost Management and Azure Monitor can split usage without an API gateway. Add APIM (Classic or V2 tier, not Consumption) only when you need token quotas per project or caller-level token metrics; note the Anthropic Messages API token metrics need a V2 tier.
- Orchestration: Durable Functions (isolated worker, Flex Consumption) or a Durable Task SDK worker on ACA, both using DTS Consumption SKU. The nightly loop is a few orchestrations with tens of actions each, so DTS Consumption cost is negligible at any plausible per-million-action price, and waiting on the human approval event costs nothing on the Consumption plan. Storage queue plus ACA event-driven job is the zero-cost alternative when you do not need approval gates or timers.
- Telemetry: Application Insights with OTLP support on, an OpenTelemetry Collector sidecar or a shared Collector in the ACA environment authenticating with managed identity, Claude Code OTLP metrics and events pointed at the Collector, Azure OpenAI diagnostic settings to the same Log Analytics workspace, Basic Logs for verbose tool-result tables, a daily cap as a safety net.
- Reporting: FOCUS export to a storage account plus the FinOps toolkit Power BI storage report (no extra services) for a small account; FinOps hubs with Data Explorer (about US$120/month) only if you need multi-tenant scopes or KQL.

## Key question 2: Does routing model calls through Azure (Foundry) give better per-project cost attribution than GitHub Copilot credits, and what does it cost per million tokens with caching?

### Takeaway
Yes for attribution, with caveats: Azure OpenAI usage is a first-party meter on a resource you control, so resource tags, per-project resources or deployments, Azure Monitor `ModelDeploymentName` splits and APIM token metrics with your own dimensions all work; Claude via Foundry arrives as a single Marketplace CCU line in Cost Management (per-model token detail only in the Foundry portal), so per-project attribution needs separate Foundry resources plus Claude Code's own `cost_usd` telemetry. GitHub Copilot moved to pooled, per-token "GitHub AI Credits" on 1 June 2026, which are attributable per user and plan but not per project or run from Azure. Cached-input pricing is 10% of input for Azure OpenAI and most Claude models, 5% for Opus 5.5 and Sonnet 5.5.

### Cited Findings
- Claude via Foundry cost visibility: "Single CCU line in Azure Cost Management; per-model token detail in the Foundry portal"; CCU is "the single billing dimension for Claude models in Foundry. One Marketplace meter replaces the previous per-model token meters." Anthropic: "Azure Cost Management shows aggregated CCU." [24 Oct 2026] [CCU billing](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/claude-models-billing); [Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing)
- Azure OpenAI metrics can be split or filtered by `ModelDeploymentName` and `ModelName`; multiple deployments of the same model under different names are allowed "to manage separate configurations or rate limits". [24 Oct 2026] [Azure OpenAI monitoring reference](https://learn.microsoft.com/azure/foundry/openai/monitor-openai-reference); [Claude in Microsoft Foundry (Anthropic)](https://platform.claude.com/docs/en/build-with-claude/claude-in-microsoft-foundry)

### Inferences
- For Azure OpenAI models, the cleanest attribution unit is one Foundry resource per project (tags flow to cost records; metrics split by deployment; quota is per subscription-region-model so splitting resources does not cost quota). ## Key question 3: How do you tag every agent run with project and run id so Azure Cost Management and Log Analytics can report cost per agent per night per project?

### Takeaway
Cost Management only knows resources, meters and resource tags at daily granularity, so project attribution lives on resources (one Foundry resource, one ACA job and one storage container per project, all tagged `project=`), while run-level and nightly attribution must come from telemetry: Claude Code `OTEL_RESOURCE_ATTRIBUTES="project.id=...,run.id=...,night=..."` flowing into Log Analytics with `cost_usd` per request, plus APIM `llm-emit-token-metric` dimensions for non-Claude agents; join the two in Power BI or KQL.

### Cited Findings
- Tag inheritance copies billing, resource-group and subscription tags onto child usage records (in cost data only, not on resources), for Enterprise Agreement, Microsoft Customer Agreement and Microsoft Partner Agreement accounts; takes 8 to 24 hours; resources that "don't emit usage at a subscription scope ... will not have the subscription tags applied". Budgets can filter on inherited tags after 24 hours. [24 Oct 2026] [Group and allocate costs using tag inheritance](https://learn.microsoft.com/azure/cost-management-billing/costs/enable-tag-inheritance)
- Cost allocation rules move or split costs between subscriptions, resource groups or tags; "Cost allocation doesn't support purchases, including reservations and savings plans"; supported only for MCA-E, MCA-online and EA, and require Enterprise Administrator or Billing account owner. [24 Oct 2026] [Create and manage cost allocation rules](https://learn.microsoft.com/azure/cost-management-billing/costs/allocate-costs)
- Tag constraints: applied directly to resources, only for resources in resource groups, only while the resource is active, not retroactive; enforce with Azure Policy; use the Tags API with Query or Cost Details APIs; the `cm-resource-parent` tag groups related resources in the Resources view. [24 Oct 2026] [Understand Cost Management data](https://learn.microsoft.com/azure/cost-management-billing/costs/understand-cost-mgt-data#how-tags-are-used-in-cost-and-usage-data); [FinOps Framework: allocation](https://learn.microsoft.com/cloud-computing/finops/framework/understand/allocation)
- Claude Code custom attributes: `OTEL_RESOURCE_ATTRIBUTES` keys are added "to every metric datapoint and event" and to the resource block; high-cardinality keys raise metric storage cost; set `OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES=false` to keep them only on the resource block (events still carry them); session id is a default metric label (`OTEL_METRICS_INCLUDE_SESSION_ID`, default true). [24 Oct 2026] [Claude Code monitoring usage](https://code.claude.com/docs/en/monitoring-usage)
- Claude Code `api_request` events carry `cost_usd`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `model`, `request_id`, `duration_ms`; `claude_code.commit.count` and `claude_code.pull_request.count` give output-side counters; `claude_code.active_time.total` gives wall-clock. [24 Oct 2026] [Claude Code monitoring usage](https://code.claude.com/docs/en/monitoring-usage)
- APIM dimensions: up to 5 custom dimensions per `llm-emit-token-metric` policy, 100 unique values per dimension, 1,000 active time series per namespace, silently discarded beyond that. [24 Oct 2026] [llm-emit-token-metric limits](https://learn.microsoft.com/azure/api-management/llm-emit-token-metric-policy#limits-for-custom-metrics)
- Azure OpenAI diagnostic settings export metrics and logs to Log Analytics for KQL joins. [24 Oct 2026] [Monitor Azure OpenAI](https://learn.microsoft.com/azure/ai-foundry/openai/how-to/monitor-openai#analyze-monitoring-data)
- ACA job executions can be started with an overridden template (environment variables, command) per execution via `az containerapp job start --yaml` or the Jobs Start REST API, so each run can receive `PROJECT_ID`, `RUN_ID`, `NIGHT` values. [24 Oct 2026] [Jobs: start on demand](https://learn.microsoft.com/azure/container-apps/jobs#start-a-job-execution-on-demand)
- Cost Management exports (FOCUS) land in storage daily and feed Power BI or Fabric; FinOps hubs add Data Explorer/Fabric for KQL. [24 Oct 2026] [Create a Fabric workspace for FinOps](https://learn.microsoft.com/cloud-computing/finops/fabric/create-fabric-workspace-finops); [FinOps hubs](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/finops-hubs-overview)

### Inferences
- Resource layout that makes Cost Management do the project split by itself: one resource group per project (`project=<id>`, `env=factory`), containing the project's Foundry resource (Azure OpenAI deployments and, if used, Claude deployments), ACA job definitions, storage for exports and artefacts, and the project's Log Analytics tables or workspace. Shared services (DTS, Collector, APIM, Application Insights) live in a `shared` resource group and are split by cost allocation rules (EA/MCA) or by telemetry ratios (pay-as-you-go, where allocation rules and tag inheritance are unavailable).
- Run-level attribution: the orchestrator mints `run.id` (the DTS instance id, max 100 chars) and `night` (UTC date) and injects them into each ACA job execution as environment variables; the job sets `OTEL_RESOURCE_ATTRIBUTES="project.id=<p>,run.id=<r>,night=<d>,agent=claude-code"` for Claude Code, and sends `x-project-id` / `x-run-id` headers through APIM for Codex or custom agents (APIM `llm-emit-token-metric` dimension on `project.id` only, since `run.id` would exceed the 100-unique-values and 1,000-series limits; log run ids in APIM logs instead).
- Keep `run.id` out of metric labels (`OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES=false` and consider `OTEL_METRICS_INCLUDE_SESSION_ID=false`) and rely on events for per-run cost; metrics then carry only `project.id`-level labels.
- Reporting join: nightly KQL over `api_request` events grouped by `project.id`, `run.id`, `model` gives measured token dollars; the FOCUS export gives billed dollars per resource tag per day; the compute share per run comes from ACA job execution start and end times multiplied by allocated vCPU and GiB. For Claude, reconcile telemetry `cost_usd` totals against the CCU line monthly (expect telemetry to be slightly lower than billing if cache-write surcharges or data-zone multipliers are missed; Claude Code's `cost_usd` is computed client-side from list prices).

### Gaps
- Whether Claude Code's client-side `cost_usd` applies the US Data Zone 1.1x multiplier or Foundry private-offer discounts was not documented.
- Pay-as-you-go (MOSA) subscriptions lack tag inheritance, cost allocation rules and FOCUS exports for FinOps hubs 0.2+; the exact export datasets available to MOSA subscriptions were not verified.

## Key question 4: What are the traps (Foundry quotas, Claude regions, Durable Functions limits, Container Apps job limits, Log Analytics ingestion cost)?

### Takeaway
The sharpest traps are commercial: Claude on Foundry cannot be bought from credit-only or sponsored subscriptions and bills a card instead of credits; default pay-as-you-go Claude quotas (40 RPM, 40K uncached input TPM, 8K output TPM) are far below what parallel coding agents need; Claude is deployable only in US regions and Sweden Central, never in Australia or Asia Pacific. Operationally: ACA jobs may be interrupted by platform maintenance and cannot run Docker; DTS caps payloads at 1 MB; GPT-5.6+ charges for cache writes; APIM AI policies need Classic or V2 tiers; Claude Code must pin model deployments and needs all three roles deployed.

### Cited Findings

- Not supported for Claude: "Enterprise Accounts located in South Korea", "Cloud Solution Provider subscriptions", "Azure subscriptions that don't have an active pay-as-you-go billing method (for example, student, free trial, or startup credit-based accounts)", "Sponsored subscriptions that only use Azure credits. Note: If you have an account with a credit card on file, the credit card will be charged instead of Azure Credits." Billing country must be one where Anthropic offers the models (Microsoft Managed Countries/Regions except Belarus and Russia). [24 Oct 2026] [Deploy and use Claude models](https://learn.microsoft.com/azure/foundry/foundry-models/how-to/use-foundry-models-claude#subscription-type-and-region-support); [Models from partners and community](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/models-from-partners)

- Default Claude quotas on pay-as-you-go: 40 RPM / 40,000 ITPM / 8,000 OTPM for the main 5.x models; 0 for Fable; Enterprise/MCA-E get 10,000 / 10,000,000 / 2,000,000. - Claude Code: pin versions or aliases fall back to Opus 4.6 and may fail with no startup check; each role needs a deployment; a URL in `ANTHROPIC_FOUNDRY_RESOURCE` is refused; deployments not named after model IDs default to a 200K window. [24 Oct 2026] [Claude Code on Microsoft Foundry](https://code.claude.com/docs/en/microsoft-foundry)
- Content filtering for Claude is not built in at deployment time. [24 Oct 2026] [Claude models in Microsoft Foundry](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/claude-models)

- Tier 1 quotas for the newest models are small (`gpt-5.6-*`, `gpt-6-*`: 250 RPM / 250K TPM Global Standard; `gpt-5.4` 2,500 / 250K); Standard deployments use "custom rate limiting behavior ... can lead to HTTP 429 errors before defined quota values are exceeded if traffic isn't evenly distributed." [24 Oct 2026] [Azure OpenAI quotas](https://learn.microsoft.com/azure/foundry/openai/quotas-limits); [Provisioned throughput](https://learn.microsoft.com/azure/foundry/openai/concepts/provisioned-throughput#monitor-utilization-and-performance)
- GPT-5.6 and later charge for cache writes; `prompt_cache_key` misses above about 15 RPM per key; PTU-M lacks breakpoints; caches expire within 5 to 10 minutes idle. [24 Oct 2026] [Prompt caching](https://learn.microsoft.com/azure/foundry/openai/how-to/prompt-caching)
- Codex CLI has no Entra ID support (API key in an environment variable only). [24 Oct 2026] [Codex with Azure OpenAI](https://learn.microsoft.com/azure/foundry/openai/how-to/codex#troubleshooting)
- Hourly PTU without a reservation is "not recommended" for production scaling; one-month commitments scope to a resource, reservations scope wider. [24 Oct 2026] [Understanding PTU costs](https://learn.microsoft.com/azure/ai-foundry/openai/how-to/provisioned-throughput-onboarding)

Container Apps traps
- Platform maintenance can interrupt long-running job replicas; set retries to at least 1 and design for at-least-once. Default `replicaTimeout` 1800 s; no documented maximum found. Execution history capped at 100. No Docker-in-Docker. Jobs do not support ingress or Dapr. Start permission leaks secrets via execution templates. Consumption workload profile image size limit 8 GB. [24 Oct 2026] [Jobs](https://learn.microsoft.com/azure/container-apps/jobs); [Runner tutorial](https://learn.microsoft.com/azure/container-apps/tutorial-ci-cd-runners-jobs); [Containers](https://learn.microsoft.com/azure/container-apps/containers)
- Quotas: "Managed Environment Consumption Cores" is per environment and must be requested separately; "Maximum Allowed Cores exceeded" errors mean a quota request; regional capacity errors are not fixed by quota. Sandboxes and Express are limited to 2,000 cores. [24 Oct 2026] [Quotas for Azure Container Apps](https://learn.microsoft.com/azure/container-apps/quotas)
- Dynamic sessions block egress by default; custom container pools run on dedicated E16 instances (cost floor); anything inside a session is visible to the session's users; managed identity exposure to the main container is "use with caution". [24 Oct 2026] [Use dynamic sessions](https://learn.microsoft.com/azure/container-apps/sessions-usage); [Billing: dynamic sessions](https://learn.microsoft.com/azure/container-apps/billing#dynamic-sessions)
- Consumption-only (legacy) environments cannot use UDR, NAT Gateway or private endpoints. [24 Oct 2026] [Networking](https://learn.microsoft.com/azure/container-apps/networking)

Durable Functions and DTS traps
- 1 MB limits on orchestrator/activity inputs and outputs, external event data, custom status and entity state; 3.9 MB per work item completion; Consumption SKU 500 actions/s, 30-day retention, no HA, 10 schedulers per region and 5 task hubs per scheduler (task hub quotas cannot be raised). [24 Oct 2026] [DTS limitations](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler#limitations-and-considerations); [DTS billing](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler-billing)
- External events are at-least-once and discarded if the instance id does not exist; failed orchestrations cannot be retried; in-process model support ends 10 November 2026. [24 Oct 2026] [External events](https://learn.microsoft.com/azure/durable-task/common/durable-task-external-events); [Durable orchestrations](https://learn.microsoft.com/azure/durable-task/common/durable-task-orchestrations)
- Durable agents built on durable entities cap the whole conversation at 1 MB and add scheduler latency; streaming is request/response with callbacks. [24 Oct 2026] [Durable Task extension for Agent Framework](https://learn.microsoft.com/azure/durable-task/sdks/durable-agents-microsoft-agent-framework#known-limitations)
- Azure Storage provider on Flex Consumption: queue polling adds storage transaction cost; always-ready instances have no free grants. [24 Oct 2026] [Azure Storage provider](https://learn.microsoft.com/azure/durable-task/durable-functions/durable-functions-azure-storage-provider); [Flex Consumption billing](https://learn.microsoft.com/azure/azure-functions/flex-consumption-plan#billing)

Telemetry and gateway traps
- Claude Code adds `session.id` as a metric label by default; each custom resource attribute becomes a metric label; high cardinality raises storage cost. [24 Oct 2026] [Claude Code monitoring usage](https://code.claude.com/docs/en/monitoring-usage)
- Application Insights OTLP experiences require delta temporality and exponential histograms; Collector needs `azure_auth` 0.148.0+; AMA path uses non-standard port 4319 for logs and traces. [24 Oct 2026] [Ingest OTLP with OTel Collector](https://learn.microsoft.com/azure/azure-monitor/containers/opentelemetry-protocol-ingestion); [Ingest OTLP with AMA](https://learn.microsoft.com/azure/azure-monitor/containers/opentelemetry-ingest-agent)
- Log Analytics commitment tiers do not cover Basic or Auxiliary ingestion and lock for 31 days; Basic/Auxiliary queries bill per GB scanned; daily cap on App Insights defaults to 100 GB/day in the portal (effectively unlimited for a small team) so set it explicitly. [24 Oct 2026] [Azure Monitor Logs cost](https://learn.microsoft.com/azure/azure-monitor/logs/cost-logs); [Daily cap](https://learn.microsoft.com/azure/azure-monitor/logs/daily-cap)
- APIM `llm-token-limit` and `llm-emit-token-metric` are unavailable on the Consumption tier; Anthropic Messages API metrics need V2 tiers; custom metrics are an Azure Monitor preview with silent discard beyond 100 values per dimension or 1,000 series per namespace. [24 Oct 2026] [Policy reference](https://learn.microsoft.com/azure/api-management/api-management-policies); [llm-emit-token-metric](https://learn.microsoft.com/azure/api-management/llm-emit-token-metric-policy)

Cost governance traps
- Tag inheritance and cost allocation rules require EA or MCA; FOCUS exports for FinOps hubs 0.2+ are not available on MOSA (pay-as-you-go) subscriptions; the Cost Management Power BI connector uses an old API and misses savings plans. [24 Oct 2026] [Tag inheritance](https://learn.microsoft.com/azure/cost-management-billing/costs/enable-tag-inheritance); [Cost allocation rules](https://learn.microsoft.com/azure/cost-management-billing/costs/allocate-costs); [FinOps hubs](https://learn.microsoft.com/cloud-computing/finops/toolkit/hubs/finops-hubs-overview)
- Visual Studio credit subscriptions have a US$0 spending limit by default and are disabled when the credit is exhausted; Cost Management still shows rated usage, which alarms people (a Q&A thread shows EUR 564 of rated Foundry usage against a US$150 credit). ### Inferences
- An Australian team wanting Claude through Foundry will run model inference in East US 2 (or Sweden Central) while compute can sit in Australia East; expect transatlantic or trans-Pacific latency per call and keep the ACA environment in the same US region as the Foundry resource to avoid it, which also keeps egress in one geography.
- With 40 RPM default Claude quota, 3 to 4 parallel Claude Code workers will hit 429s on bursts of subagent calls; request a quota increase before the first night or put APIM token limits in front to smooth traffic.
- Plan nightly runs as chains of ACA job executions (one per task) orchestrated by DTS rather than one 8-hour execution, which sidesteps the undocumented `replicaTimeout` ceiling and the maintenance-interruption risk, and gives natural per-task run ids.

### Gaps
- Maximum `replicaTimeout` for ACA jobs.
- Azure Monitor workspace (Prometheus) pricing and sample limits.
- Current GitHub-hosted runner minute prices and included minutes per plan after the January 2026 price cut.

## Key question 5: Which parts are covered by Azure credits and which are commonly not (marketplace, third-party models, support plans)?

### Takeaway
Azure credits (MCA credits, Sponsorship, Microsoft for Startups, Visual Studio monthly credits) pay for first-party Azure consumption: Container Apps, Functions, Durable Task Scheduler, Storage, Log Analytics, API Management, Key Vault, networking and Foundry models "sold directly by Azure" (Azure OpenAI GPT-5.x, Codex and GPT-6 included). They do not pay for Marketplace or partner models (Anthropic Claude, Cohere, Hugging Face, select Meta and Mistral), Azure support plans, non-Azure licences, reserved instances or savings plans (Sponsorship), and Visual Studio credits also exclude Application Insights and Azure DevOps.

### Cited Findings
- MCA credit exclusions: "Partner-provided products or services, along with non-Microsoft products on Microsoft Marketplace", "Azure support plans", "Software subscriptions or licenses that aren't billed as Azure consumption"; Sponsorship additionally excludes "Entitlement-based purchases, even when Azure sells those offerings directly (for example, savings plans or reserved instances)". "Azure Sponsorship credits might cover models that Azure sells directly" and "don't cover models from partners and the community." [24 Oct 2026] [Track your Azure credit balance for an MCA](https://learn.microsoft.com/azure/cost-management-billing/benefits/credits/mca-check-azure-credits-balance#products-and-services-that-azure-credits-don't-cover)
- Microsoft for Startups policy: "Startup credits apply to Microsoft Foundry models that are sold and billed directly by Azure. Models billed by third-party providers (including Anthropic), partner services, or available through the Microsoft Marketplace are not eligible." Providers not covered: Anthropic, Cohere (select), Hugging Face, Meta (select), Mistral AI (select). Use the "Direct from Azure" collection in the Foundry portal to find eligible models. [24 Oct 2026] [Microsoft for Startups credit coverage for Foundry models](https://learn.microsoft.com/en-us/microsoft-for-startups/build/foundry-model-sponsorship-coverage)
- Azure Sponsorship (partner programs): "100% discounted Azure usage of first-party Azure workloads ... off published pay-as-you-go retail rates"; cannot be applied to reserved instances, reserved capacity, "third-party marketplace purchases, services, or support (entitlement purchases)"; offsets consumption so it does not count toward MACC; only on PAYG, EA and MCA billing accounts, not CSP; auto-switches to PAYG or EA rates when exhausted or expired. [24 Oct 2026] [Use Grow Azure sponsorship](https://learn.microsoft.com/partner-center/frontier-accelerate-marketplace/grow/azure-sponsorship#azure-sponsorship-limitations); [Use your Azure credits (Partner Center)](https://learn.microsoft.com/partner-center/benefits/mpn-benefits-azure-cloud)
- Visual Studio subscriber monthly credit excludes "Support plans, Application Insights, Visual Studio subscriptions, Azure DevOps, Visual Studio App Center, Third-party branded products, Products sold through the Visual Studio Marketplace, Products otherwise sold separately from Azure (for example, Microsoft Entra ID P2)"; dev/test only, no SLA, instances running more than 120 hours continuously may be suspended, lower default quotas. [24 Oct 2026] [Azure for Visual Studio subscribers FAQ](https://learn.microsoft.com/visualstudio/subscriptions/faq/subscriber/azure/)
- Claude on Foundry is a Marketplace SaaS purchase: credit-only and sponsored subscriptions cannot buy it, and a card on file is charged instead of credits. Microsoft Q&A answers confirm startup credits do not offset Claude usage and that MACC eligibility is a separate concept for EA commitments. [24 Oct 2026] [Deploy and use Claude models](https://learn.microsoft.com/azure/foundry/foundry-models/how-to/use-foundry-models-claude#subscription-type-and-region-support); [Q&A: start-up credits and Claude](https://learn.microsoft.com/answers/a/12380529); [Q&A: Founders Hub and Claude](https://learn.microsoft.com/answers/a/12408137)
- CCU spend is MACC-eligible and "decrements your Microsoft Azure Consumption Commitment the same way any other Azure Marketplace consumption does" (relevant for EA/MCA commitments, not for credits). [24 Oct 2026] [CCU billing](https://learn.microsoft.com/azure/foundry/foundry-models/concepts/claude-models-billing)
- Conflicting community claim: a 2025 Q&A answer said Azure OpenAI "is considered a Marketplace service ... not covered by Founders Hub Credits", which is contradicted by the official Microsoft for Startups coverage page and the MCA credits page stating Azure-sold models are covered; treat the Q&A answer as wrong or outdated. [Q&A, undated] [Q&A: Founders Hub credits coverage](https://learn.microsoft.com/answers/a/1874652); contradicted by [Microsoft for Startups coverage](https://learn.microsoft.com/en-us/microsoft-for-startups/build/foundry-model-sponsorship-coverage)
- Durable Task Scheduler, Container Apps, Functions, Log Analytics, API Management and Storage are first-party Azure meters (billed by Microsoft on the Azure invoice), so they fall under "first-party Azure consumption" in the sponsorship terms. [24 Oct 2026] [DTS billing](https://learn.microsoft.com/azure/durable-task/scheduler/durable-task-scheduler-billing); [Billing in ACA](https://learn.microsoft.com/azure/container-apps/billing); [Azure Monitor billing meters](https://learn.microsoft.com/azure/azure-monitor/fundamentals/cost-meters)

### Inferences
- A credits-funded factory should route model calls to Azure OpenAI deployments (GPT-5.5, GPT-5.4, GPT-5.3-Codex, GPT-6 family) if the goal is zero cash outlay; Claude via Foundry requires a pay-as-you-go payment method and bills cash regardless of credit balance, and on a sponsored subscription the deployment may be refused outright.
- Hybrid pattern: keep the Claude Code fleet on Claude via Foundry in a separate pay-as-you-go subscription (or Anthropic direct), and keep compute, orchestration, telemetry, reporting and any Codex or GPT workers on the credit subscription; both subscriptions can export FOCUS data into the same storage account for one Power BI model.
- Avoid FinOps hubs' Data Explorer or Fabric capacity if credits are Sponsorship: Fabric capacity is first-party and should be covered, but reservations for it are not, and Visual Studio credits would not cover Application Insights at all.
- GitHub Copilot AI Credits are a GitHub product and never touch Azure credits.

### Gaps
- Whether Microsoft Fabric capacity and Power BI Pro licences are credit-eligible under each program was not verified (Fabric is Azure consumption, Power BI Pro is a licence and probably not).
- Whether Claude CCU spend is eligible for MACC under a Microsoft Customer Agreement without an Enterprise motion was not confirmed beyond the general "MACC-eligible" statement.

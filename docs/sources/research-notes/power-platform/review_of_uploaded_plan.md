# Review of the uploaded "Software Factory Plan" (Boroon, 1 November 2026)

Source document: "End-to-End Specification: The GET AI Microsoft Software Factory" plus "Copilot Studio Agents & App Builds", authored by Boroon Mahanta, uploaded 1 November 2026. Markdown conversion: uploaded_plan_pandoc.md (YAML indentation lost in that conversion); the original YAML with indentation: uploaded_plan_yaml.txt (both in this folder).

The reader agreed with this review and asked for a combined plan that applies these fixes and focuses on Lane B for Power Platform. Microsoft is about to rename Power Platform; the plan must make the name easy to swap.

## What the uploaded plan contains

Part A (high level): Copilot Studio intake agent (clarifying questions, glossary.md, requirement spec, JSON payload) -> "Chief of Staff" orchestrator on Azure AI Foundry plus Microsoft Agent Framework -> "Wayfinder" planning agent writes ADO Epics and User Stories with predecessor links -> Sign-Off Seam (humans set Epic to "Approved for Factory") -> overnight "Azure AutoGen" workers in non-prod Dev sandboxes (Power Platform via pac CLI; Fabric/Azure via PySpark notebooks and Bicep; Security via KQL and Sentinel in an audit-only subscription) -> red/green implementation, commit to an integration branch per Epic, agent marks ticket Resolved -> Code Review agent against ADRs and code smells, Playwright or unit tests, PR body with Summary and Evidence, Merge Danger (two-way versus one-way door) and Blast Radius -> humans merge in the morning, Dev toward UAT/Prod. Guardrails: Factory Manifestos per practice (5 practices), constraint by design (Bicep policies, branch protection, SonarQube), "Executive Chef" training, weekly Retro skill run by AI Managed Services that turns repeated agent mistakes into manifesto updates.

Part B (Power Platform blueprint, built for GitHub Enterprise with data residency at getai.ghe.com, ADO Boards and Power Platform):
- Work queue: ADO Boards (getai org), stories tagged factory-eligible, "Ready to build".
- Dispatcher and orchestrator: scheduled GitHub Actions with OIDC (token.actions.getai.ghe.com); preflight health; pulls the ADO queue; assigns one story to one isolated environment lane.
- Execution agent: GitHub-hosted ubuntu-latest; headless Claude Code (or a custom Python wrapper); reads CLAUDE.md, branches, edits, applies to Dataverse, opens the PR; identity "OIDC -> Pipeline App Reg".
- Factory environments: a pool of 3 long-lived Dev environments (factory-lane-1..3) holding manual Teams and secret connections; Dataverse Workflow App Reg.
- PR checks: GitHub Actions with the Pipeline App Reg: builder check (run every builder, then `git diff --exit-code`), `create_schema.py --plan` and `create_security.py --plan`, `lint_logic_apps.py` (if() expressions over 8,192 chars or unsafe substrings), `check_root_components.py`, `run_workflow.py --suite all` scenario tests.
- Review agent: GitHub Actions, Pipeline App Reg plus an LLM API key; evaluates the diff against CLAUDE.md, scores Merge Danger, auto-merges if safe.
- ADO state machine: GitHub webhook to an Azure Function or central Action; branch created -> Building; PR opened -> Testing; PR merged -> UAT Ready. Custom fields: Factory Eligible (bool, human sets when acceptance criteria complete), Merge Danger Score (int, review agent), Blocked Reason (text, execution agent). Parking: agent exits with a specific code on a human-only step; orchestrator sets "Awaiting business", writes the question to Blocked Reason, pulls the next story.
- Merge Danger 0 to 10: 0-2 auto-merge (docs/, state.md, tests, generated JSON/XML matching its builder, suite 100% pass); 3-5 human (interface changes needing sync_agent_tools.py, workflow builder edits, reference data); 6-10 human (security roles, schema changes and column drops, money logic, pipeline YAML, credentials). Auto-merge gate: score <= 2 AND checks green AND drift check (sync_solutions.py) shows no unintended changes; merge with gh CLI.
- System prompts: execution agent (code over click-ops, PARK on portal-only steps, never inject identity, rely on x-ms-object-id; design first for user-facing changes and halt for an approved mock; one branch; update state.md and docs/lessons-learned.md); review agent (score, builder correspondence, scenario coverage, blast radius summary if >2, drift is a blocker).
- Environment pool: per-run environments impossible without human consent (Teams OAuth, hierarchy security exclusions). Bootstrap by a human once; nightly automated preflight (pac connection list, hierarchysecurityconfiguration, Entra app permissions vs manifest; failure marks the lane Offline and raises an ADO bug); per-story reset (reset_environment.py deletes transactional test data and re-imports the main-branch solution).
- 6b testing gap: until Microsoft opens the Copilot Studio conversation API for the new harness, the factory proves workflows via run_workflow.py; the morning digest lists PRs that changed agent tools or instructions so a human spends about 5 minutes in the Copilot Studio test pane before merge.
- Phased rollout: Phase 1 Safety Net (days 1 to 14, PR checks on the existing human-led VS Code process); Phase 2 ADO automation (days 15 to 21); Phase 3 Night Shift (days 22 to 45, queue at 5 pm, review 9 to 10 am); Phase 4 Dark Factory (day 45+, auto-merge for 0-2).
- Risks: Entra eventual consistency (5 to 15 minutes; deterministic polling); runaway cost loops (token budget or max 5 loops per ticket, then park); Dataverse 429 throttling across 3 lanes (exponential backoff); GitHub-hosted runner timeouts (recommends self-hosted runners on Azure Container Apps or VMs with pac CLI, Python 3.11 and MAF pre-baked); distinct AI identity for auditing (a dedicated service principal such as ai-factory-execution-agent-dev).

## Keep (strengths)
- Rollout starts with the safety net on today's human-led work: verifier before worker.
- The orchestrator owns ADO state, not the agent (Part B section 3).
- PARK exit code plus Blocked Reason: the right answer to a material question at night (same idea as V2.1's questions.md).
- Builder determinism check and the --plan schema and security checks: deterministic, cheap, hard to fool once locked.
- The environment pool with human bootstrap, nightly preflight and per-story reset: an honest answer to the Power Platform consent problem.
- Design-first halt for user-facing changes.
- Merge Danger, blast radius and one-way versus two-way doors in the PR: a better morning package than V2.1's; adopt for every lane.
- Honest gap 6b on Copilot Studio conversation testing.
- The risks section (Entra delay, Dataverse 429s, iteration cap, distinct AI identity).

## Must fix (blocking)
1. Auto-merge on an LLM score, including test edits (Part B section 4, Phase 4). Score 0-2 includes "tests", so an agent could weaken a test and merge it unseen: the soft test-gaming path the research warns about (outright tampering about 2%, but about 80% of agent-written test patches have weak oracles, and about 20% of tests-passing patches are semantically wrong; LLM judges are generous out of the box). Auto-merge also needs the merging identity to bypass the human approval rule: the bypass-list trap. Fix: never auto-merge changes to tests, scripts, builders, workflows, hooks, CLAUDE.md or other agent instructions; compute a floor score deterministically from changed paths and `--plan` output, where the LLM may raise but never lower it; auto-merge only into a Dev or integration branch, never into anything that deploys to UAT or Prod; enter Phase 4 on evidence (for example 30 days of escaped-defect data, evaluator-human agreement at target, zero tampering detections), not on a date.
2. The PR checks run the agent's own scripts with real credentials (section 2 YAML). run_workflow.py, the lint scripts and the builders come from the PR branch, so the agent can edit the checks it is judged by, and the job holds `id-token: write` against the Dataverse app registration while running PR code. Fix: the gate is a required workflow in a separate repo the agent cannot write (organisation ruleset "Require workflows to pass"), running trusted copies of the check scripts from that repo or main; push ruleset on scripts/, workflows/build/, .github/, tests and CLAUDE.md; restrict the factory-pool environment with deployment branch rules; least-privilege, split jobs.
3. No independent acceptance tests. Humans refine acceptance criteria in ADO, but nothing turns them into executable tests the agent did not write; "red/green" has the agent write code and tests; the Review Agent checks coverage of the agent's own tests. Fix: "Factory Eligible" means criteria complete AND acceptance scenarios (run_workflow.py scenarios, and UI tests where relevant) written by someone other than the worker and locked; a held-out scenario set lives in the gate repo.
4. One identity does everything. Execution, verification and review all use "Pipeline App Reg", contradicting section 1's "strict separation of duties" and risk 5. Fix: four identities: execution (write only to its own lane environment, push only to agent branches), verification (read and plan), review (read only, cannot merge), merge (a human, or a GitHub App with no bypass); one app registration per lane so a lane cannot touch another lane's environment.
5. Two architectures in one document. Part A (Foundry plus MAF "Chief of Staff", "Azure AutoGen" workers, agent marks tickets Resolved, integration branch per Epic) conflicts with Part B (GitHub Actions dispatcher, headless Claude Code, orchestrator owns state, PR per story to main). "Azure AutoGen" is not a product: Microsoft Agent Framework is "the direct successor" to Semantic Kernel and AutoGen and "focuses on single-process composition today; distributed execution is planned" (https://learn.microsoft.com/agent-framework/overview/; AutoGen migration guide https://learn.microsoft.com/agent-framework/migration-guide/from-autogen/). Azure AI Foundry is now Microsoft Foundry. Fix: Part B is the architecture; keep Copilot Studio and Wayfinder only as an optional intake front door; drop the custom Foundry orchestrator (Actions, ADO and the agent runtime already do that job; building it is the IKEA trap).

## Should fix
6. Money. Headless Claude Code with an "LLM API key" bills at cash, not SPD credits; Copilot CLI or SDK with Claude models via Copilot is credit-funded (AI credits). The plan has no cost ledger, no run_id, no cost per agent, night or project. Back the iteration cap with a per-story budget (`--max-budget-usd`, `--max-ai-credits` or SDK `sessionLimits.maxAiCredits`) and a night envelope.
7. Data residency. GHE.com can store repos in Australia (GHE.com Australia region; network details list australiaeast and australiacentral). GitHub's "GitHub Copilot with data residency" page (GitHub Docs source, content/admin/data-residency/github-copilot-with-data-residency.md, read 1 November 2026) says inference data residency is "currently available" in the United States and European Union only, enforced through the "Restrict Copilot to data residency compliant models" policy; the EU list includes Claude Opus 5.5 and Sonnet 5.5 and GPT-6.x; data-resident requests carry a 10% model multiplier. Claude in Microsoft Foundry has no Australian region (US regions and Sweden Central). The Anthropic API is offshore. So no engine in the uploaded plan keeps inference in Australia today. Azure OpenAI in Australia East is the likely residency-safe option, but check the deployment type, because Global deployments can process data outside Australia. Decide per client before running client code.
8. The evaluator only reads the diff. The Anthropic workshop's best catches only appeared by using the app (FastAPI route ordering that passed unit tests, a delete key Boolean bug). run_workflow.py covers workflows; canvas and model-driven apps need a separate click-through evaluator session; keep the human check for Copilot Studio conversations unless a testing API now covers it.
9. Three lanes share one PR test environment: the YAML uses a single FACTORY_ENV_URL. Map lane to environment by PR label or branch prefix; add a concurrency group per lane so a reset cannot land mid-check.
10. Runner claim. Risk 4 says self-hosted runners "eliminate" timeouts. Self-hosted jobs are capped at 5 days and queued jobs drop after 24 hours (GitHub Docs); Container Apps jobs default replicaTimeout to 1,800 seconds (AVM module) with no documented maximum, and Microsoft warns that platform maintenance can interrupt long replicas (set retry at least 1, design for at-least-once) (https://learn.microsoft.com/azure/container-apps/jobs#advanced-job-configuration). Stories of 30 to 60 minutes fit the 6-hour hosted cap. Go self-hosted for pre-built images and private networking, not for time; make runs resumable.
11. The Retro Loop needs transcripts. Runner disks vanish and GitHub now deletes workflow runs and checks after the retention period (from 1 October 2026). Upload each story's transcript and JSON output to Blob, tagged with run_id.
12. Spec level. Wayfinder writes granular stories with dependencies; fine for issue-sized Power Platform work, but keep stories to what and why plus acceptance scenarios, not technical step lists (granular up-front technical plans cascade errors, per the Anthropic workshop).
13. One-way door detection should be deterministic: create_schema.py --plan flags drops; path rules flag security roles, pipeline YAML and credentials.

## Fit with V2.1
Part B is a strong Power Platform profile of V2.1's Lane B. Fold it in with fixes 1 to 4; adopt Merge Danger and the environment pool pattern for every lane; Copilot Studio becomes an optional business-user front door feeding the Spec Kit gate and ADO. Board lens: the pool, reset, preflight and Merge Danger rubric are reusable IP (pillar 2) and Power Platform depth strengthens the Microsoft moat (pillar 3); auto-merge is the one step that can damage the production track record (pillar 4).
